# PostgreSQL гарантирует отсутствие пересечений

PostgreSQL запрещает пересечения любых бронирований через `EXCLUDE USING gist` с оператором `&&` на диапазонах `tstzrange(starts_at, ends_at, '[)')`, поэтому защита действует и при прямой записи в БД, а смежные встречи допустимы. При записи API блокирует общую строку календаря через `FOR UPDATE`, затем заново проверяет текущее время и занятость в той же транзакции. Конфликт при проверке и нарушение этого ограничения при вставке дают `409 TIME_CONFLICT`, чтобы гость мог выбрать другое время.
