# Инструкции для разработки

[README.md](./README.md) описывает пользовательские сценарии, границы демо и настройку окружения. Перед исследованием кода читай [правила работы с предметной областью](./docs/agents/domain.md), [словарь](./GLOSSARY.md) и относящиеся к задаче [ADR](./docs/adr/).

## Продукт и интерфейс

- Учебное демо общедоступно и рассчитано на вымышленные контакты. Любой посетитель может создать событие и увидеть контакты в списке предстоящих встреч. Гостевая страница записи самостоятельна, без навигации управления. Каталог, доступное время и подтверждение сохраняют приватность контактов других гостей.
- Установка обслуживает одного организатора и один календарь. При создании события сервер выдаёт постоянный UUID v4 hex. Сохраняй старые строковые id, гостевые ссылки и бронирования.
- В пользовательских текстах используй «событие» для формата, «встреча» для подтверждённой записи и «свободное время» для слотов. Названия разделов — «События» и «Предстоящие встречи». Используй «Создать событие», «Событие создано» и «К событиям». На страницах управления достаточно одного основного заголовка.

## API и база данных

- Меняй контракт в TypeSpec и запускай `mise run generate`. Явно задавай OpenAPI 3.1 и используй один документ для Orval и datamodel-code-generator. Фронтенд обращается к API через сгенерированный Fetch SDK с TanStack Query. FastAPI использует сгенерированные Pydantic-модели для транспорта, а обработчики и ORM пишутся вручную. Сгенерированные файлы обновляй только генерацией.
- Используй SQLAlchemy asyncio и psycopg 3 async. Выделяй отдельную `AsyncSession` каждому запросу и параллельной задаче. Изменения схемы оформляй миграциями Alembic.
- Перепроверяй время и занятость в транзакции при подтверждении. Сохраняй общую блокировку календаря и ограничение PostgreSQL, описанные в [ADR о пересечениях](./docs/adr/0002-booking-overlap.md). При `409 TIME_CONFLICT` предлагай гостю выбрать другое время.
- Храни начало и окончание как `timestamptz`, сравнивай моменты в UTC и отображай в IANA-часовом поясе календаря. Учитывай [границы локальных дат и переходы времени](./docs/adr/0003-calendar-time.md). Ответы управления, включая ошибки, должны иметь `Cache-Control: private, no-store`.

## Команды и проверки

- Устанавливай закреплённые зависимости через `mise run setup`. Для разработки используй PostgreSQL в Compose, `mise run migrate` и `mise run dev`. При изменении команд или переменных обновляй [README.md](./README.md#установка).
- Перед коммитом запускай `mise run lint`. `pre-commit` повторяет эту проверку после `setup` или `hooks:install`. Для полной проверки используй `mise run check` с отдельной БД `TEST_DATABASE_URL`, имя которой оканчивается на `_test`.
- Проверяй соответствие FastAPI контракту, актуальность генерации и затронутые пользовательские сценарии. Проверяй конкурентные бронирования на PostgreSQL, включая ровно один успех при пересечении, а также границы дат и переходы времени. Сообщай, какие проверки выполнены и какие недоступны.
- Сохраняй имя репозитория и [workflow Хекслета](./.github/workflows/hexlet-check.yml) в исходном виде.

## Коммиты и трекер

- Используй Conventional Commits (`type(scope): описание`, область необязательна). Для несовместимых изменений добавляй `!` и пояснение перехода в `BREAKING CHANGE:`.
- В теле каждого нового коммита реализации указывай связанный тикет отдельной строкой `Refs #<номер>`, например `Refs #13`.
- Перед работой с GitHub Issues читай [правила трекера](./docs/agents/issue-tracker.md). Перед триажем и назначением меток читай [словарь меток](./docs/agents/triage-labels.md).
